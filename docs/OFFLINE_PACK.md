# חבילת אופליין — פורמט מוצע (אפיון §6.2, §19.7)

מסמך זה מגדיר טיוטה לפורמט קובץ החבילה (`assets.pack`) שמאפשר התקנה ראשונה
של המודולים והתלויות **ללא אינטרנט**. זו נקודת אפיון פתוחה — הפורמט כאן הוא
הצעה למימוש בשלב ד׳.

## דרישות
* קובץ **בודד** שהמשתמש מניח בתיקיית התוכנה.
* התוכנה מזהה אותו בהפעלה, **מאמתת שלמות**, ומתקינה ממנו את הרכיבים.
* גרסאות — כדי שהתוכנה תדע אם החבילה מתאימה/עדכנית.

## מבנה מוצע
החבילה היא ארכיון ZIP (סטנדרטי, נתמך בספריית התקן של פייתון `zipfile`) עם סיומת
`.pack`, ובתוכו:

```
assets.pack (zip)
├── manifest.json          # מטא-דאטה + חתימות שלמות
├── models/
│   └── embed-he-mini/...   # מודל ה-Embeddings (§8.2)
├── calendar/
│   └── hebcal.json         # נתוני לוח עברי (אם לא מחושבים בקוד)
├── lexicon/
│   └── topics.json         # מילון תגיות מעודכן (§8.2 שכבה 1)
└── bin/
    └── yt-dlp...           # ספריית ההורדה (§11)
```

## `manifest.json`
```json
{
  "pack_format": 1,
  "created": "2026-01-01T00:00:00Z",
  "app_min_version": "0.1.0",
  "components": [
    {
      "name": "embed-he-mini",
      "type": "model",
      "target": "models/embed-he-mini",
      "sha256": "<hash>",
      "size": 148000000
    },
    {
      "name": "topics-lexicon",
      "type": "lexicon",
      "target": "lexicon/topics.json",
      "sha256": "<hash>"
    }
  ]
}
```

## תהליך אימות והתקנה
1. בהפעלה — חפש `*.pack` בתיקיית התוכנה.
2. פתח את ה-ZIP וקרא את `manifest.json`; ודא `pack_format` נתמך ו-`app_min_version`.
3. עבור כל רכיב: חשב `sha256` על התוכן וודא שהוא תואם ל-manifest (שלמות).
4. חלץ לרכיבים ליעד ב-`data/` של האפליקציה; סמן כמותקן (עם מספר גרסה).
5. במקרה של אי-התאמה — הצג שגיאה ברורה בעברית ("חבילת האופליין פגומה או לא
   מתאימה לגרסה").

> נקודת מימוש: אפשר לחתום את ה-manifest עצמו (חתימה אסימטרית) אם רוצים לוודא
> שהחבילה הופקה על-ידי הארגון, מעבר לבדיקת שלמות בלבד.
