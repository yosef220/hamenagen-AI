# ארכיטקטורה — המנגן 1.1

שני תהליכים על אותו מחשב: **חלון Electron** שמציג ומנגן, ו**ליבת Python** שמבינה, מסווגת וזוכרת. הם מדברים בשורות JSON על stdio — בלי שרת, בלי פורט פתוח ובלי תלות ברשת.

```
┌───────────────────────────── חלון המנגן · Electron ─────────────────────────────┐
│  renderer/ (ממשק)  ◄──►  preload.js (רשימה סגורה)  ◄──►  main.js (תהליך ראשי)   │
│  מסכים · נגן · תור · בקשה      בלי גישה ישירה למערכת       חלון · מהדורה · נתונים │
└──────────────────────────────────────────┬──────────────────────────────────────┘
                                           │ JSON-RPC על stdio: בקשות, תשובות ואירועים
┌──────────────────────────────── הליבה · Python ─────────────────────────────────┐
│ rpc.py → service.PlayerService                                                  │
│   intent · fuzzy      classifier · topics · knowledge      hebrew_calendar      │
│   scanner · index_db  vocal (מאזין לשירים)   fetcher · radio · updater         │
└────────────────────────┬───────────────────────────────────┬────────────────────┘
                 על המחשב: SQLite, מודל, מוזיקה        ברשת (רק כשיש): יוטיוב, קול חי, GitHub
```

## הליבה (`backend/hamenagen`)

| קובץ | תפקיד |
| --- | --- |
| `rpc.py` | לולאת JSON-RPC. בקשות מהירות נענות מיד ובסדר; בקשות רשת וארוכות (חיפוש, הורדה, רדיו, עדכונים) רצות על מאגר תהליכונים; עבודה על כל הספרייה (סריקה, מודל, סיווג מחדש) רצה ברקע ומדווחת באירועים (`scan_progress`, `scan_done`, `model_install`, `download_progress` …). |
| `service.py` | נקודת הכניסה היחידה: מחבר את כל המודולים, מרכיב רשימות לבקשה, לוח היום, סיכום הספרייה, מועדפים והיסטוריה. אחרי כל סריקה ותיקון הוא מפיץ נושאים: שיר שאף שכבה לא סיווגה מקבל את הנושא של רוב השירים באלבום (או בתיקייה) שלו, כשלפחות שלושה מהם מסווגים ו-60% מהם מסכימים. |
| `intent.py` | מפרק בקשה בעברית לכוונה ופרמטרים: נושא, משך („שעה של…”), כמות, אחרונים, מועדפים, היסטוריה, הכי מושמעים, חיפוש שיר, אקראי. |
| `text_normalize.py` | נרמול: ניקוד, אותיות סופיות, מפרידים, ראשי תיבות (ל״ג → לג), ותחיליות (לשבת → שבת). |
| `fuzzy.py` | התאמה רב-שדתית ששורדת כתיב שונה וסדר מילים אחר. |
| `classifier.py` · `topics.py` | סיווג בשכבות, מהבטוח למשער: שם שיר מהרשימה של המנגן → אינדקס השירים → מילת מפתח (גם בשם האלבום והתיקייה) → זמר → אוצר המילים של המועדים → מודל הטמעה מקומי. המודל (multilingual-e5-small, ONNX Runtime, גרסה נעולה) משווה את השיר לביטויים טיפוסיים של כל מועד (`data/topic_exemplars.json`) ומחליט רק מעל סף ובפער ברור מהמועד השני. לכל החלטה נשמר הסבר קצר („אינדקס השירים: „יה ריבון עלם” (ויקיפדיה)”) שמוצג בתפריט השיר. ההשוואה בין מודלים: `scripts/benchmark_models.py`. |
| `knowledge.py` | אינדקס הידע. `SongIndex` — שירים ופיוטים לפי מועד, עם כתיבים אחרים ושמות שרק מתחילים בשם מוכר („אשת חיל מי ימצא”). `TopicLexicon` — משקלי TF-IDF של מילים וצמדי מילים לכל מועד; שיר מקבל מועד רק כשהוא מוביל בבירור. שני קובצי הנתונים (`data/song_index.json`, `data/topic_lexicon.json`) נבנים ב-`scripts/build_knowledge.py` מוויקיפדיה העברית ומספריא ונמדדים ב-`scripts/eval_knowledge.py`. |
| `vocal.py` | זיהוי שירים ווקאליים מהשמע: שלושה חלונות של 10 שניות (ב-20%, 50% ו-80% של השיר) מפוענחים ב-soundfile, ספקטרוגרמה ב-numpy, ומודל CED-Tiny (‏int8, ‏6MB) מתייג כל חלון. „ווקאלי” רק כששני חלונות לפחות שומעים שירה בלי כלים ואף חלון לא שומע כלי נגינה מובהק; „אולי” בסף נמוך יותר. כחמישית שנייה לשיר, ברקע, תהליכון אחד. |
| `hebrew_calendar.py` | המרה לתאריך עברי (Rata Die), גימטריה, כל מועדי היום, ספירת העומר, דחיית תשעה באב, המועד הבא. |
| `scanner.py` | סריקת תיקיות; דילוג על תיקיות מערכת, צלילים קצרים וקבצים שלא השתנו (גודל + זמן שינוי). |
| `index_db.py` | SQLite במצב WAL, בטוח לשימוש מכמה תהליכונים: שירים (עם הנושא, התגיות וההסבר), מועדפים, השמעות, ההחלטות של המאזין (`overrides` — נושא שבחר, ווקאלי כן/לא; אף פעם לא מחושבות מחדש), ומה שזיהוי הווקאלי שמע (`audio_analysis`, כולל ציון לכל חלון, כדי שאפשר יהיה לשנות סף בלי להאזין שוב). |
| `fetcher.py` | חיפוש והורדה מיוטיוב דרך `yt-dlp`, מאחורי ממשק מקור מתחלף. |
| `radio.py` | ערוצי קול חי מתוך `ServerModel.live`, עם מטמון ורשימה שמורה לאופליין. |
| `updater.py` | בדיקת `update.json` של הגרסה האחרונה (לפי מהדורה), ועדכון yt-dlp ומילון הנושאים. |
| `settings.py` | הגדרות JSON ונתיבים לפי משתני הסביבה שהחלון מעביר. |

## החלון (`electron/`)

| קובץ | תפקיד |
| --- | --- |
| `main.js` | מהדורה ותיקיית נתונים, מופע יחיד, גודל חלון זכור, ערכת צבעים לשורת הכותרת, בוחר תיקיות, כפתורי נגן בשורת המשימות, קיצור דרך לגרסאות ה-ZIP. |
| `backend_bridge.js` | מפעיל את הליבה (Python מוטמע בגרסה הארוזה), מתאם תשובות לפי מזהה, מעביר אירועים, מפעיל מחדש אחרי נפילה ושומר יומן ב-`data/logs/core.log`. |
| `preload.js` | הגשר היחיד לממשק (contextIsolation + sandbox), כולל בניית כתובת `file://` לשירים. |
| `renderer/` | הממשק: `js/util.js` (עזרים, עברית), `api.js`, `player.js` (נגן, תור, טיימר, Media Session), `components.js`, `views/*` (בית, תוצאות, ספרייה, נושאים, רדיו, הורדות, הגדרות), `app.js` (ניווט ואתחול). עיצוב ב-`styles/tokens.css` (צבעים לשתי הערכות) ו-`styles/app.css`. גופנים, אייקונים ו-hls.js נשמרים מקומית ב-`vendor/`. |

## החלטות

1. **stdio ולא HTTP** — אין פורט, אין חומת אש, אין שרת שצריך לנהל.
2. **אופליין קודם** — כל רכיב חכם עובד בלי רשת; כל תלות חיצונית עטופה כך שהיעדרה רק מצמצם יכולת.
3. **מילון לפני מודל, ומודל שנבחר במדידה** — דיוק מלא לשירים מוכרים, והמודל רק משלים. השוואה של שישה מודלים על שמות שירים בעברית הראתה שהשיטה חשובה יותר מגיל המודל: משפט תיאור אחד לכל מועד נתן 22%–29% לכל המודלים; אוצר מילים לכל מועד עם multilingual-e5-small נתן 89% על שמות באוצר המילים ו-52% על ניסוח חדש. המודל קטן (ONNX, בלי PyTorch).
4. **ידע לפני ניחוש (1.1)** — מה שחסר למודלים הקטנים הוא ידע על המועדים, לא הבנת עברית. לכן 1.1 מוסיף ידע מפורש, קטן ופתוח: אינדקס של שירים ופיוטים ואוצר מילים לכל מועד, מוויקיפדיה ומספריא. מודלי שפה מקומיים (Qwen 3.5, ‏Gemma 4, ‏DictaLM 3.0) נבדקו ונדחו: 14%–38% דיוק, 0.5–3GB ושנייה עד ארבע לכל שיר. גם NLI נבדק ונדחה.
5. **המאזין מחליט** — כל זיהוי אוטומטי (נושא או ווקאלי) אפשר לתקן בלחיצה, והתיקון נשמר בנפרד מהסיווג ולא נדרס בסריקה הבאה. שירים שזוהו כווקאליים מהשמע מחכים לאישור ונכנסים להצעות של ימי הספירה רק אחריו (אלא אם המאזין ביקש אחרת), כי טעות כאן עולה יותר מהחמצה.
6. **מועד גובר על שבת** — ביום שישי של חנוכה ההצעה היא חנוכה, ושירי שבת מוצעים לידה.
7. **אותיות במקום תמונות** — לכל שיר „עטיפה” מהאות הראשונה שלו בצבע הנושא; אין תלות בתמונות מהרשת.

## בדיקות

- `backend/tests` — ליבה: לוח עברי, הבנת בקשות, סיווג, אינדקס הידע (גם על הקבצים שנשלחים), תיקונים והפצה לפי אלבום, זיהוי ווקאלי (הכלל, קריאת החלונות עם מודל מדומה, והשפעה על הספרייה), ספרייה, סריקה מצטברת, הורדה, עדכונים, לולאת RPC.
- `tests/ui` — מריץ את התוכנה האמיתית מול ספריית דוגמה ועובר על כל המסכים בשתי הערכות, כולל תפריט השיר, תיקון נושא ורשימת האישור של שירים ווקאליים.
- ב-CI, לכל מהדורה ארוזה: בדיקה שהליבה הארוזה עונה לבקשות, שאינדקס הידע עובד, ושזיהוי הווקאלי מפענח ומתייג שמע אמיתי; ובגרסת האופליין — שמודל הסיווג נטען בלי רשת.

## המדידות מאחורי 1.1

**סיווג.** שלושה מבחנים: 102 תיאורים של שירים (כיול), 65 בניסוח חדש (לא שימשו לכיול) ו-136 שמות שירים אמיתיים כפי שהם בשמות קבצים, כולל 30 שירים שאינם שייכים לשום מועד. הפקודה: `python backend/scripts/eval_knowledge.py --model-dir <תיקיית המודל>`.

**זיהוי ווקאלי.** 30 הקלטות ברישיון חופשי: 12 בלי כלים (מקהלות, חזנות, אקפלה, „הנרות הללו”) ו-18 עם כלים (רוק, כליזמר, הקלטות עבריות ישנות עם תזמורת, עוגב ומקהלה). CED-Tiny מצא 9 מתוך 12 (6 „ווקאלי” ו-3 „אולי”) בלי אף התראת שווא; YAMNet מצא 3, ‏CLAP מצא 7 וכבד פי 5. מה שהמודל מחמיץ: שירה שמחקה להקה (בס ווקאלי, ביטבוקס) — שם עדיין עובדות המילים בשם השיר.
