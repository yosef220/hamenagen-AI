# ארכיטקטורה — המנגן 1.0

שני תהליכים על אותו מחשב: **חלון Electron** שמציג ומנגן, ו**ליבת Python** שמבינה, מסווגת וזוכרת. הם מדברים בשורות JSON על stdio — בלי שרת, בלי פורט פתוח ובלי תלות ברשת.

```
┌───────────────────────────── חלון המנגן · Electron ─────────────────────────────┐
│  renderer/ (ממשק)  ◄──►  preload.js (רשימה סגורה)  ◄──►  main.js (תהליך ראשי)   │
│  מסכים · נגן · תור · בקשה      בלי גישה ישירה למערכת       חלון · מהדורה · נתונים │
└──────────────────────────────────────────┬──────────────────────────────────────┘
                                           │ JSON-RPC על stdio: בקשות, תשובות ואירועים
┌──────────────────────────────── הליבה · Python ─────────────────────────────────┐
│ rpc.py → service.PlayerService                                                  │
│   intent · fuzzy      classifier · topics      hebrew_calendar                  │
│   scanner · index_db  fetcher (yt-dlp)         radio · updater · offline_pack   │
└────────────────────────┬───────────────────────────────────┬────────────────────┘
                 על המחשב: SQLite, מודל, מוזיקה        ברשת (רק כשיש): יוטיוב, קול חי, GitHub
```

## הליבה (`backend/hamenagen`)

| קובץ | תפקיד |
| --- | --- |
| `rpc.py` | לולאת JSON-RPC. בקשות מהירות נענות מיד ובסדר; בקשות רשת וארוכות (חיפוש, הורדה, רדיו, עדכונים) רצות על מאגר תהליכונים; עבודה על כל הספרייה (סריקה, מודל, סיווג מחדש) רצה ברקע ומדווחת באירועים (`scan_progress`, `scan_done`, `model_install`, `download_progress` …). |
| `service.py` | נקודת הכניסה היחידה: מחבר את כל המודולים, מרכיב רשימות לבקשה, לוח היום, סיכום הספרייה, מועדפים והיסטוריה. |
| `intent.py` | מפרק בקשה בעברית לכוונה ופרמטרים: נושא, משך („שעה של…”), כמות, אחרונים, מועדפים, היסטוריה, הכי מושמעים, חיפוש שיר, אקראי. |
| `text_normalize.py` | נרמול: ניקוד, אותיות סופיות, מפרידים, ראשי תיבות (ל״ג → לג), ותחיליות (לשבת → שבת). |
| `fuzzy.py` | התאמה רב-שדתית ששורדת כתיב שונה וסדר מילים אחר. |
| `classifier.py` · `topics.py` | סיווג בשכבות: שם שיר ידוע → מילון → זמר → מודל הטמעה מקומי (fastembed/ONNX). כל התאמה נוספת נשמרת כתגית. |
| `hebrew_calendar.py` | המרה לתאריך עברי (Rata Die), גימטריה, כל מועדי היום, ספירת העומר, דחיית תשעה באב, המועד הבא. |
| `scanner.py` | סריקת תיקיות; דילוג על תיקיות מערכת, צלילים קצרים וקבצים שלא השתנו (גודל + זמן שינוי). |
| `index_db.py` | SQLite במצב WAL, בטוח לשימוש מכמה תהליכונים: שירים, תגיות, מועדפים, השמעות, מטא-דאטה. |
| `fetcher.py` | חיפוש והורדה מיוטיוב דרך `yt-dlp`, מאחורי ממשק מקור מתחלף. |
| `radio.py` | ערוצי קול חי מתוך `ServerModel.live`, עם מטמון ורשימה שמורה לאופליין. |
| `updater.py` | בדיקת `update.json` של הגרסה האחרונה (לפי מהדורה), ועדכון yt-dlp ומילון הנושאים. |
| `settings.py` | הגדרות JSON ונתיבים לפי משתני הסביבה שהחלון מעביר. |

## החלון (`electron/`)

| קובץ | תפקיד |
| --- | --- |
| `main.js` | מהדורה ותיקיית נתונים, מופע יחיד, גודל חלון זכור, ערכת צבעים לשורת הכותרת, בוחר תיקיות, כפתורי נגן בשורת המשימות, קיצור דרך לגרסאות ה-ZIP. |
| `backend_bridge.js` | מפעיל את הליבה (Python מוטמע בגרסה הארוזה), מתאם תשובות לפי מזהה, מעביר אירועים, מפעיל מחדש אחרי נפילה ושומר יומן ב-`data/logs/core.log`. |
| `preload.js` | הגשר היחיד לממשק (contextIsolation + sandbox), כולל בניית כתובת `file://` לשירים. |
| `renderer/` | הממשק: `js/util.js` (עזרים, עברית), `api.js`, `player.js` (נגן, תור, טיימר, Media Session), `components.js`, `views/*` (בית, תוצאות, ספרייה, נושאים, רדיו, הורדות, הגדרות), `app.js` (ניווט ואתחול). עיצוב ב-`styles/tokens.css` (צבעים לשתי הערכות) ו-`styles/app.css`. גופנים, אייקונים ו-hls.js נשמרים מקומית ב-`vendor/`. |

## איפה נשמר מה

| מה | איפה |
| --- | --- |
| ספרייה, הגדרות, מועדפים, היסטוריה | גרסה ניידת: `data` ליד `Hamenagen.exe` (או `%APPDATA%\Hamenagen` אם אי אפשר לכתוב שם). גרסה מותקנת: `%APPDATA%\Hamenagen`. פיתוח: `data/` במאגר. |
| מודל הסיווג | גרסת האופליין: `resources/models` בתוך התוכנה. אחרות: `models` בתיקיית הנתונים, יורד פעם אחת. |
| הורדות | `מוזיקה\Hamenagen` של המשתמש (ניתן לשינוי). |
| יומן הליבה | `logs/core.log` בתיקיית הנתונים. |

## החלטות

1. **stdio ולא HTTP** — אין פורט, אין חומת אש, אין שרת שצריך לנהל.
2. **אופליין קודם** — כל רכיב חכם עובד בלי רשת; כל תלות חיצונית עטופה כך שהיעדרה רק מצמצם יכולת.
3. **מילון לפני מודל** — דיוק מלא לשירים מוכרים, והמודל רק משלים. המודל קטן (ONNX, בלי PyTorch).
4. **מועד גובר על שבת** — ביום שישי של חנוכה ההצעה היא חנוכה, ושירי שבת מוצעים לידה.
5. **אותיות במקום תמונות** — לכל שיר „עטיפה” מהאות הראשונה שלו בצבע הנושא; אין תלות בתמונות מהרשת.

## בדיקות

- `backend/tests` — ליבה: לוח עברי, הבנת בקשות, סיווג, ספרייה, סריקה מצטברת, הורדה (עם מקור מדומה), עדכונים, חבילת אופליין, לולאת RPC.
- `tests/ui` — מריץ את התוכנה האמיתית מול ספריית דוגמה ועובר על כל המסכים בשתי הערכות.
- ב-CI, לכל מהדורה ארוזה: בדיקה שהליבה הארוזה עונה לבקשות, ובגרסת האופליין — שהמודל נטען בלי רשת.
